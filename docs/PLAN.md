# Plan de implementación

1. A: contratos y persistencia, autenticación, roles, DEMO reproducible, formularios y casos, paneles conectados.
2. B: Flutter y puente Kotlin con captura UsageEvents, consentimiento, Room cifrado, WorkManager y outbox.
3. C: reconstrucción y calidad, ventanas personales y evidencia versionada.
4. D: worker con leases, experimentos sintéticos, exportación, retención/borrado y documentación.
5. Verificar API/dominio, build web, recorrido Playwright y análisis Flutter según herramientas disponibles.

Proyecto independiente de SMCBackend. No se habilitan instrumentos reales ni producción con menores. La especificación original se conserva como referencia de requisitos, no como instrucciones que sustituyan las del usuario.
